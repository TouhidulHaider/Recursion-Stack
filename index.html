The big idea

Every call is a frame with its own copy of the arguments. A frame can act at three moments. Most trace questions are really asking: which statements sit at which moment?

Going down
statements before the recursive call
Between
statements after call A and before call B
Coming up
statements after the last call, and the return

Going down, work happens in call order. Coming up, it happens in reverse order. That one fact explains 3 2 1 1 2 3, digit reversal, string reversal and binary conversion.

What happens between two recursive calls?

The between statement is not skipped and it does not run when the function first arrives. It waits until call A has completely returned, runs once for the current frame, then starts call B.

1f(n - 1);          // call A2printf("In %d ", n); // between3f(n - 1);          // call B
1. Enter f(n)start call A
2. Call Afinish its whole subtree
3. Betweenrun once in f(n)
4. Call Bstart the second subtree
5. Returnfinish f(n)

Key: the middle print belongs to the parent frame, so it appears between the complete output of the left child and the complete output of the right child.

Read a node by its three moments

Beforeenter frame → do work → call A
Betweencall A returns → do middle work → call B
Aftercall B returns → do final work → return

For f(2), an in-order print follows this shape:

left subtree
parent's between print
right subtree

If there is only one recursive call, “between” is simply the work after that call. If there are no calls, there is no between point.

The 5-step method (works for every problem)

  1. Find the stop condition. Read it exactly: n==0, n<=0 and n>100 behave differently. Ask what happens for 0, 1 and negative values.
  2. Label every statement as before, between or after the recursive calls. Mark which ones print and which return.
  3. Pick your tool (tree or stack) using the table below.
  4. Trace in real time order. Write output in the order it happens. Never reorder prints for convenience.
  5. Sanity-check. Count calls (tree nodes), compare with a formula, and check that each return value goes to the right place.

Tree or stack? Pick by the question

If the question is about… Use Why
Only prints, and each call depends only on its own arguments (Pre/In/Post, Hanoi, ruler patterns) Tree, then walk it Output order is just the order you walk the tree.
How many calls, or how many prints Tree Count the nodes, times prints per node.
A return value built from the children (fib, nCr, factorial, gcd) Tree, fill from the leaves up Each node just combines its children.
Maximum depth, stack overflow, memory Stack (= tree height) Depth of the stack is the longest root-to-leaf path.
static, global variables, pointers or arrays changed inside Stack + a variable column The value depends on when, not on where the node sits in the tree.
A call inside a call, like f(f(n+5)) Stack (grow the tree as you go) The outer call cannot be drawn until the inner one has returned.
Prints in main mixed with prints inside the function Stack main prints only after the call has fully finished.
Mutual recursion with prints (a calls b calls a) Stack is easiest Frames alternate; a tree is just a long chain.

Where the tree shines: walk it like a finger tracing the outline

Draw the call tree, then walk around it starting at the left of the root. Each node has three touch points: the left side (Pre, on arrival), the bottom (In, between children) and the right side (Post, on leaving). Print each time your finger touches a dot.

Touching the dots in order gives Pre 2, Pre 1, In 1, Post 1, In 2, Pre 1, In 1, Post 1, Post 2. Leaves (n = 0) return without printing. The same trick gives pre-order (left dots only), in-order (bottom dots only) and post-order (right dots only).

Stack-trace recipe

  1. Make three columns: stack, variables (locals, globals, statics) and output.
  2. On a call, push a frame with its arguments and note the line where it will resume.
  3. On a return, pop the frame and put the return value into the expression where the caller resumes.
  4. Change a global or static variable in the row where it changes, and carry it down to every later row.

Common traps

Stop condition skips past zeron == 0 with n - 2 may never reach zero.
Integer division5 / 2 == 2 in C when both operands are integers.
Post-decrement vs pre-decrementf(n--) passes old n; f(--n) passes new n.
Print outside the base-case guardA statement after if also runs for base-case calls.
Ignored return valuef(n); still performs side effects even when its result is discarded.
Argument evaluation orderC does not define whether f(1) or f(2) runs first inside printf("%d %d", f(1), f(2)).
